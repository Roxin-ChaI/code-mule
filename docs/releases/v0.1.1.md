## User-visible changes

- Fixed workspace Git baseline isolation: Code Mule state remains outside the
  target's deliverable change set without hiding unrelated workspace changes.
- Added safe `WORKSPACE_BLOCK` retry after restoring the clean pre-dispatch
  baseline; uncertain execution is not converted into a safe retry.
- Added Worker Input answer/continuation lifecycle:
  `code-mule answer <action-id> "<answer>"` records the answer to a pending action,
  preserves partial work, and does not start a Worker. A later explicit
  `code-mule run` revalidates the original baseline and starts a fresh Worker
  session for the same Task; no partial commit or transparent session recovery.
- Added bounded Worker timeout policy: production CLI uses 120-second inactivity
  and 900-second hard turn limits. Trusted current-turn activity refreshes only
  inactivity. Timeouts preserve work and fail closed, with no automatic Worker retry.
- Added Codex failure diagnostics: typed failure source, identity, activity and
  elapsed timing, with safe bounded metadata rather than raw messages or secrets.
- Added typed Worker human actions for input, approval, and external side effects.
  Native input requests and typed end-of-turn input reports share the answer lifecycle.
- Separated Worker verification from Git ownership failures. Verification blocks
  have a dedicated HumanAction and `inspect --verbose` diagnostics.
- Added required/optional verification semantics: required must PASS; optional
  NOT_RUN is permitted, but optional FAIL/UNKNOWN remains blocking. Exact path
  ownership, clean baseline, HEAD, staged-file safety and one Task/one delivery
  commit remain strict. No verification-only automatic recovery is introduced.

## Runtime and state compatibility

- Package version: **0.1.1**; Python **>=3.12,<3.13**.
- **Real E2E validated with Codex CLI 0.153.4**. This is not a proven minimum
  supported version. Older 0.147.0 references describe initial development only.
- **ProjectState schema v11** preserves the v1→v11 migration chain. Legacy checks
  without required/optional evidence remain conservatively required. Unsupported
  schema versions fail closed.
- Back up ProjectState before upgrading. New state may not be readable by an
  older Code Mule version; forward migration is not a downgrade guarantee. Do
  not edit schema numbers manually to force compatibility.
- Required flags remain a Worker reporting trust boundary because Task acceptance
  criteria are natural language, not deterministic required-check IDs. No name-based
  inference or validator bypass is introduced.
