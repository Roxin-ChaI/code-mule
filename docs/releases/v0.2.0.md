# v0.2.0 — Release Candidate

Status: automated release audit passed; Boss manual RC E2E required. This
preparation does not create a tag, push, or GitHub Release.

- Package version: **0.2.0**; Python **>=3.12,<3.13**.
- ProjectState schema: **v16**, with supported migration input **v1..v16**.
- Existing annotated tags remain immutable:
  `v0.1.0` targets `dd56a9bd026215ff4dec57f2f63bf59456c74f4d` and

## Frozen capability set

The RC contains the existing deterministic lifecycle: onboarding and planning,
single-Worker execution, structured Supervisor review, typed HumanAction and
recovery, post-completion revisions, exact-path Git delivery, required-check
verification, DeliveryManifest handoff, owned local runtime launch/health/stop,
persistent TUI, completed-project control, state-schema compatibility, and the
persistent installer/doctor diagnostics.

No new Agent capability, parallel Worker, daemon, Web UI, remote delivery, or
automatic Human Gate approval is added by this release preparation.

## Automated quality gate

- **947 tests PASS**, including a model-free release smoke suite that routes
  every public CLI command through its typed composition boundary.
- `compileall src tests scripts`, `pip check`, and `git diff --check` PASS.
- The local release-readiness E2E covers planning, CHANGE/replanning, unique
  Worker sessions, one commit per accepted Task, final verification/review,
  cancellation, bounded Worker timeout, interruption recovery, lease release,
  and a clean disposable workspace.
- Automated checks do not read an API key or call DeepSeek/Codex.

## Boss manual RC gate

Before tagging or publishing, the Boss must run one authenticated disposable
flow and retain its evidence:

```text
new project → start → Worker → DONE → deliverable
→ launch → health → stop → change → Revision 2 → DONE → TUI
```

Any failure blocks the release. Do not move or recreate historical tags.
